## 学生界面方案（待实施）

1. 保留当前三个判断和揭示释义后的下一词/上一词/记错了流程。
2. 单词默认显示带重音的规范形式，如 чита́ть；规范词头 word/lemma 不改，accent 存显示形式，查询时去除组合重音但不能把 ё 全替换成 е。单音节通常不另加重音；多重音、异义异读和 ё 相关例外按具体词典记录，不机械套规则。
3. 动词标题下显示“未完成体 / 完成体”，双体动词单独标注。释义揭示后并列显示“чита́ть（未完成体）— прочита́ть（完成体）”，相关词可点击查看小详情，再返回原词。不强制跳下一题，不自动加入学习队列，也不把认识一个体当成两个词都掌握。
4. 初学者默认同时看到相关体词和对应中文；进阶场景可折叠。只链接相同义项下有词典依据的体配对，允许一对多、双体、无常用配对和暂未确认，不根据前缀自动判作完成体配对。
5. 基础词汇入口按已核实教材/课程单元安排，并保留专四、专八词库。不能把专四词库简单改名为“大一基础”。需要用户提供大一使用教材及目标单元；年级只作推荐，学生仍可自由选词库。

## 纠错方案

问题不只是 OCR。规则可以找到异常字符，却无法可靠识别“西珠牙”这种全是正常汉字的错误。LLM 回译、自我互审只能提供候选，不能成为正确证明。

1. 优先处理学生报错、初学高频词、缺中文核心义和可疑词头；现有学习记录与词条 ID 保持不动。
2. 每词以俄文规范词头为起点，比较原资料及可靠俄中词典释义，重音和体查俄语词典。模型提出简洁中文修正，不盲目扩充所有义项。
3. 重点核对 е/ё、о/б、阴阳性/体标记混入、地名中文错字、缺义、串词和多义词。无法确定的非必要例句删去或暂不展示；核心词头/词义不能确认时从新词抽取中暂缓，保留原记录供继续核对。
4. 登记修改前后值和来源；“释义通过、重音待核对”分别保留。不要以整批没报错为全词通过。
5. 先做 100 个基础高频词作为试用样本，再分批覆盖现有词库。修正后的内容必须检查实际背词接口及复习池展示；服务器以定向内容更新同步，代码更新不会自动修改旧库。
