## Skills 的冲突与边界

1. `skill-creator` 的“只保留会改变决策的非显然信息”“按风险决定约束强度”与本轮目标一致。项目 Skill 仅保留内容审核特有规则，授权统一引用 AGENTS。
2. `openai-docs` 要求针对官方产品问题先搜索并获取官方页面。这不应扩展为“每次编辑本地 AGENTS 都先查询模型宣传或升级配置”。本轮将其作为被审查文本，未执行模型迁移流程；请求官方模型事实时仍按适用规则查证。
3. PDF Skill 的默认渲染优先与本项目“可复制页先直取”存在工作方式差异；项目内容 Skill 明确按页分流。创建/编辑 PDF 成品才涉及其制品标记流程，单纯读源文件或提取内容不要机械套用制品交付步骤。缺少工具时先寻找现有 PDF 渲染替代能力，避免直接要求用户手工处理。
4. `kwai` 的提交确认作用于向外部提交 Agent 会话数据，是独立用途的授权边界；不能为了提高 AIeyu 开发自主性而取消，也不应触发于普通题库任务。本轮未运行该服务或读取会话内容。
5. 通用插件缓存由安装/更新流程维护，直接改会被覆盖且影响其他项目；本轮不修改。项目新增 `.agents/skills/aieyu-content-review/SKILL.md`，并由 AGENTS 显式指向，当前任务可直接读取；不假定宿主已热加载新 Skill。

## 借鉴范例的取舍

- 采用：中文结论优先、当前用户决定优先、自主完成已授权工作、先做可检查结果、适度测试、独立任务才并行委派。
- 补充：授权的数据/用途/预算范围、阻塞只影响依赖步骤、数据库独立备份、原文审核覆盖、生产更新数据保护。
- 不复制：飞书 CLI、固定 Chrome 偏好、CLAUDE 兼容入口等本项目没有需求的规则；不把任一模型称呼写成必须更换产品架构的条件。
- 一处维护一个职责：AGENTS 管协作，CURRENT_STATE 管当前事实，PRD 管产品契约，Skill 管内容处理，历史只作查证。

## 产品优化顺序

1. 先修发布内容更新链路。现有补丁按新值直接覆盖，审核日志又按当前状态回写；这会妨碍后续人工修改的保留和历史追溯。下一次发布前应在副本上验证旧值前置条件、冲突输出、补丁顺序及备份。当前需求为规则审查，本轮未更改业务脚本或数据。
2. 补齐内容审核证据。保留题号、页码、原值/新值和状态；把未审核范围与实际错误清单分开。先解决缺题干、缺选项及阅读段落绑定，避免以清零审计数量替代内容质量。
3. 评估诊断与专项效果。现有样本少，保留粗方向和低样本提示；区别首次作答与重复练习带来的分数改善。不要立即引入复杂画像模型。
4. 按缺题方向扩充语法/词汇。小规模验证检索依据、唯一答案、干扰项质量和跨批去重；测得检索不足再考虑向量索引。RAG 召回率需要带相关性标注的评测集，不能凭运行成功估算。

## 行为验收场景

| 用户请求/条件 | 优化后行为 |
| --- | --- |
| “按原标准全部做完”且范围明确 | 持续按批处理到范围完成，更新覆盖记录，不每批请求继续 |
| “同意发送这两个知识块生成两题” | 完成这两题及检查，不自动扩大到全库 |
| 文档仍问是否需要登录 | 查当前契约与代码，更新旧问题，不重新问用户 |
| 少数原页无法辨认 | 完成可确认内容，未决项列出依据及最小所需信息，不编造 |
| 用户要求打包更新 | 准备更新包、数据补丁和操作步骤；保留服务器学生库，不擅自部署 |
| 测试全通过但只审核部分题 | 报告测试通过及实际覆盖，不称全库正确 |
| 外部调用权限不足 | 处理平台批准并完成独立工作；真实阻塞说明原因，不循环询问同一决定 |
| 文档小改 | 检查差异、链接及规则冲突，不运行付费 API 和全套业务流程 |

这些是本轮规则审查用例，已逐项与新文档人工对照；不是模型自动执行能力的量化评测。
