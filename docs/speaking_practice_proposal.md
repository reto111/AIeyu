# 俄语实时口语陪练方案

日期：2026-09-24。状态：选型建议，尚未获准实施或调用新的收费语音服务。
范围：用户要求能听懂学生俄语、实时语音回应、连续对话；服务个人备考，不建设教师端或社交功能。

2026-10-27 仓库整理说明：工作区已有 `scripts/serve_speaking_app.py`、`scripts/speaking_runtime.py` 和 `requirements-speaking.txt` 草稿，本次随当前进度归档，仅做 Python 语法检查。未安装或验收语音运行环境，未连接语音供应商、接入学生界面或部署；不把这些草稿计为已交付口语功能。本记录不新增收费服务或音频外发授权。

## 推荐结论

首版采用浏览器WebRTC + Python语音模块 + 流式ASR + 现有DeepSeek + 流式TTS。
优先验证阿里云百炼俄语识别与合成，Pipecat负责语音处理流程。
以云端语音API完成识别、合成，不先在现有服务器部署大模型，不先购买GPU。
不需要LangChain、模型训练或新增向量数据库。普通口语聊天不要求RAG，已有词库和薄弱点用数据库直接读取。

## 两条路线

| 路线 | 优点 | 局限 | 本项目选择 |
| --- | --- | --- | --- |
| ASR -> 文本LLM -> TTS | 可沿用DeepSeek；每步可查；方便中文反馈与更换供应商 | 延迟累加；转写丢失语调和部分口误 | 首版推荐 |
| 原生语音到语音 | 可直接处理音频、自然接话及打断 | 网络、地区、价格、俄语教学效果需单独实测；审阅不能只依赖转写 | 后续同一测试集对比 |

OpenAI Realtime为原生语音路线候选，官方支持音频直接交互、会话状态和工具调用：[官方说明](https://developers.openai.com/api/docs/guides/realtime)。是否适合实际用户地区、账号与网络，需要验证，不承诺可直接在现有部署使用。

## 技术选择

| 层 | 首选候选 | 接入要点 |
| --- | --- | --- |
| 浏览器采集播放 | getUserMedia、WebRTC、Pipecat浏览器SDK | 桌面/手机共用页面，首次点开始请求麦克风，启用可用的回声消除 |
| 语音流程 | Pipecat | 管理音频帧、流式服务、轮次、取消；固定经过测试的版本 |
| 说话检测 | Silero VAD或经验证的服务端VAD | VAD只判断是否在说话，不等于语义上说完 |
| ASR | 百炼俄语实时ASR | 候选qwen-audio-3.1-asr-flash-streaming；也可比较qwen3-asr-flash-realtime；选账号地域中实际可用版本 |
| 文本生成 | 现有DeepSeek，独立流式调用 | 复用Key与模型配置，关闭长推理，短回复；不直接调用现有阻塞接口 |
| TTS | qwen3-tts-flash-realtime系列内置音色 | 官方列俄语，逐音色测试；需要语速指令时再验证instruct版本 |
| 保存 | 现有SQLite及账号体系 | 只增加口语会话、轮次与反馈，不复制用户表 |

百炼文档明确列出实时ASR俄语支持及WebSocket输入输出：[ASR](https://help.aliyun.com/zh/model-studio/asr-model)。TTS应选支持俄语的具体版本和音色，不把同一品牌所有声音都当作多语言：[TTS](https://help.aliyun.com/zh/model-studio/tts-model)。需要为选定语音服务实现/验证Pipecat适配器；框架有Qwen文本插件不等于这两项语音API即插即用。

## 开源项目

| 项目 | 本项目用途 | 取舍 |
| --- | --- | --- |
| [Pipecat](https://github.com/pipecat-ai/pipecat) | Python语音流程，DeepSeek适配与打断机制 | 推荐只采用这一套语音编排 |
| [Pipecat Web客户端](https://github.com/pipecat-ai/pipecat-client-web) | 网页连接、音频和事件处理 | 嵌入现有界面，不照搬演示页面 |
| [Silero VAD](https://github.com/snakers4/silero-vad) | 说话起止检测 | 轻量组件，不承担识别或口语评分 |
| [LiveKit Agents](https://github.com/livekit/agents) | 完整WebRTC语音Agent方案 | 与Pipecat作为替代选项比较，不同时堆两套Agent框架 |
| [faster-whisper](https://github.com/SYSTRAN/faster-whisper) | 后续自托管ASR、离线复核 | 本身不自动解决实时轮次与播放；当前低配服务器不优先运行大模型 |

开源程序不等于免费语音服务；代码、模型权重、音色分别检查许可证。Pipecat当前仓库为BSD-2-Clause；LiveKit Agents为Apache-2.0，但其轮次模型有单独许可，不能一概而论。

## 如何嵌入现有系统

当前scripts/serve_student_app.py使用ThreadingHTTPServer；deepseek_chat使用stream=False，等待整段JSON返回。
保留现有练习/单词服务，在同一仓库新增小型异步语音进程，通过现有域名反向代理接入；不为了口语重写全部网站。
建议结构为speaking下的session、providers、prompt、feedback几个文件，不引入通用多Agent平台。

```text
学生登录 -> 主应用验证身份与额度 -> 签发短时会话凭证
浏览器麦克风 <-> WebRTC语音进程
                     -> VAD/轮次判断 -> 俄语ASR
                     -> DeepSeek流式短回复
                     -> 按短句分段TTS -> 浏览器播放
会话结束 -> 独立生成中文反馈 -> 经身份校验写回主应用SQLite
```

- 主应用只提供少量当前级别、场景、目标词及必要薄弱点，不外发整库或个人姓名。
- ASR部分结果只展示临时字幕，最终结果再进入已确认轮次；允许用户标记识别错了。
- 按句子或合理短语送TTS，不逐字合成，也不等整篇结束再发声；处理俄语缩写、姓名缩写和小数中的句点。
- 用户插话时，取消未完成LLM/TTS，清空服务器和浏览器待播队列；以轮次ID丢弃迟到结果。上下文不把未播完的话误记成学生已经听到。
- 每位用户独立会话状态；凭证服务端绑定登录身份，不能相信客户端提交的user_id。
- 新增speaking_sessions、speaking_turns、speaking_feedback；记录语言级别、转写、纠错、完成状态、耗时和用量。异步语音模块通过内部接口短事务写入，音频不存SQLite。
- 沿用数据库迁移及一致性备份，不覆盖服务器学生库。功能开关可单独关闭口语，不影响现有练习与单词。

## 首版界面与练习

新增独立“口语”页面，无虚拟人物、装饰大球或复杂仪表盘。
顶部为场景和水平，中央为当前对话与可收起字幕，底部固定麦克风/暂停/结束控制；移动端不覆盖内容。
状态明确区分正在听、正在组织回答、正在播放、网络异常，等待时用小型转圈而非长时间空白。

首版只保留三个入口：

1. 场景对话：自我介绍、校园生活、购物、出行等少量人工设定场景。
2. 单词活用：从当前已审核词库选3至5个学过的词，放入对话任务；口语中使用不能直接把单词标成已掌握。
3. 自由交流：沿用水平标签，用户可主动调节难度。考试模拟待核对应考试要求后再命名上线。

年级只是默认起点，不能直接等同CEFR等级；结合学生自选与实际表现调整。
初学者使用短句、慢速、一次一个问题；允许中文求助，显示可选俄语回答提示。
连续通话是主体验，按住说话作为噪声或断网后的降级选项，不将录完上传冒充实时对话。
学生停顿较多，初始可试约1至1.5秒静音再接话；这是待调参数，不是准确终止句子的判据。

## 教学与反馈

对话中优先交流，明显妨碍理解时才立即澄清；多数语法问题在结束后简短呈现。
建议每轮俄语1至3句、只问一个问题；结束反馈最多3项：原句、自然表达、中文原因，并允许重说。
不自动输出未经校准的口语总分；不把一次识别错误计入薄弱知识点，不自动覆盖选择题画像。
ASR可能把学生说错的形式自动修成正确句子，也可能误听：保留转写为观察结果，疑似误听先确认。
转写准确率不等于发音准确率。重音、软硬音、颤音及元音弱化评分需要额外音频证据和经教师验证的评测方案，首版不假装能精确评分。
字幕重音、TTS输入分开处理：组合重音符是否支持须实测，不能盲删ё或假设加符号就一定念对。
RAG仅在讨论教材、国情等需来源依据时按需使用；普通对话和结束反馈不每轮检索整本PDF。

## 教学提示词草案

你是AIeyu的俄语口语陪练。根据传入的学习水平、场景及目标词调整语言；默认用俄语短句交流，每次最多提出一个问题，让学生多说。初学者可用中文求助，你给出简短中文提示后回到俄语。不要因学生停顿就替他说完。听不清或转写可疑时请求重复，不编造学生原话，不据此判定语法错误。除妨碍理解的问题外，不在每一轮打断纠错。结束时仅总结最多三个可确定的问题，给出原句、建议表达及中文说明；不把转写结果当作发音评分，不声称已听清未收到的音频。

## 部署与费用

- 公网麦克风页面需要HTTPS；localhost测试属于例外，普通公网HTTP不能当正式方案：[MDN](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。
- 原2核4GB Windows实例若配置未变，可先尝试少量并发的API转发与音频处理，承载量必须压测；不假定它能运行高质量ASR/TTS大模型或承载整个班级同时通话。
- 首先在Windows隔离虚拟环境验证依赖，不更换用户本地操作系统。后期若需Linux语音节点，可单独部署，不迁移整站作为前置条件。
- SmallWebRTC可用于小规模原型；公网须测试STUN/TURN、UDP受限、移动网络等情况，不能仅开放网站TCP端口就认为音频必通。规模扩大后再比较同地域RTC托管或LiveKit，而不是预先搭复杂集群：[Pipecat传输选型](https://docs.pipecat.ai/client/concepts/choosing-a-transport)。
- 模型Key仅服务端.env；浏览器只拿短时会话凭证。供应商Key区域与接口端点一致。
- 首次使用说明音频将发送到所选语音供应商。默认不持久化原始录音，转写与反馈提供删除入口；调试录音另征同意并限时保存。
- 费用由ASR计费时长、TTS文字/音频量、LLM输入输出、RTC与流量组成。不同模型计费单位不同，按实际账号地域价格核算，不能把10分钟通话直接等同10分钟TTS。
- 先测完整10分钟会话的真实账单，再计算班级预算。服务端限制每天分钟数、单次时长、并发及费用上限；结束/断线必须关闭上游连接，避免空挂计费。

## 实施顺序及验收

1. 先做俄语语音能力验证：征得授权后，用20至30条覆盖初学者口音、慢速停顿、中俄混说、е/ё及重音区别的样本，比较识别与合成。只测元音数量或文档声称支持俄语不算验收。
2. 打通单会话链路：麦克风、ASR字幕、流式DeepSeek、分句TTS和播放；记录每段耗时，优先解决主要瓶颈。
3. 加入连续对话、插话、暂停、回声控制、断线处理；验证AI声音不会被当作学生输入。
4. 接入账号、已审核词库、场景和级别；结束后生成简短中文反馈，不抢占实时对话链路。
5. 少量学生试用：Windows Chrome、Android Chrome、iPhone Safari和Wi-Fi/移动网络；拒绝麦克风、后台切换、TTS失败都要能恢复。微信内置浏览器另外实测，不宣称天然兼容。
6. 分别压测1/3/5并发，核服务CPU/内存、首声延迟、误打断、回复串线及账单，再决定开放人数。回归现有账号、单词、练习；打包仅包含代码、依赖及迁移，不覆盖生产数据库。

建议验收目标而非现有性能承诺：从学生说完到首个可听回复P50不超过2至3秒、P95不超过5秒；插话后约0.5秒内停播。使用同一批用户样本测ASR词错误率和教师判读的任务理解率，同时单独检查俄语重音、自然度和错误纠正可靠性。若不达标，先调整轮次等待、模型与句段长度，不用加载动画掩盖延迟。
